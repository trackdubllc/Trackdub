Trackdub uses a centralized .NET dependency management strategy built on MSBuild Central Package Management (CPM) with per-project lockfiles, supplemented by GitHub Dependabot for automated update PRs.

**System and tools**
- **MSBuild Central Package Management**: `Directory.Packages.props` is the single source of truth for all third-party package versions across the monorepo. Each `<PackageVersion Include="..." Version="..." />` entry pins an exact version, and projects reference packages without inline versions.
- **Per-project lockfiles**: Every `.csproj` restores with `packages.lock.json` (enforced via `RestorePackagesWithLockFile=true` in `Directory.Build.props`). This guarantees reproducible builds by pinning transitive dependencies per project.
- **NuGet sources**: `NuGet.config` declares two sources — `nuget.org` as primary and `dotnet-libraries` (Azure Artifacts public feed) for preview-only packages like `Microsoft.ML.Tokenizers` 3.x. A `packageSourceMapping` restricts that preview package to the secondary feed while everything else resolves from nuget.org.
- **SDK/runtime pinning**: `global.json` pins the .NET SDK to `10.0.300` with `rollForward: latestFeature`, and `mise.toml` pins toolchain versions (`dotnet 10.0.302`, `node 22.16.0`, `pnpm 11.15.1`) for development environments.
- **Automated updates**: `.github/dependabot.yml` schedules weekly scans for both `github-actions` and `nuget` ecosystems, capping open PRs at 10.

**Key files**
- `Directory.Packages.props` — central version definitions for all NuGet packages, including explicit comments explaining special cases (e.g., Lucene.Net beta analyzers, Microsoft.ML.Tokenizers preview, LibVLCSharp LGPL redistribution notes).
- `Directory.Build.props` — global MSBuild properties enabling CPM (`ManagePackageVersionsCentrally=true` is set in Directory.Packages.props), lockfile restore, nullable/implicit usings, and target framework `net10.0`.
- `NuGet.config` — package source configuration and `packageSourceMapping` routing preview-only packages to the dotnet-libraries Azure feed.
- `global.json` — .NET SDK version pin.
- `mise.toml` — developer toolchain version pinning.
- `.github/dependabot.yml` — weekly automated update policy for GitHub Actions and NuGet packages.
- Per-project `packages.lock.json` files (one per `.csproj`) — deterministic transitive dependency snapshots.

**Architecture and conventions**
- All third-party dependencies are declared exclusively in `Directory.Packages.props`; individual projects never specify versions inline.
- Preview or pre-release packages are isolated with explanatory comments documenting why they cannot be moved to stable nuget.org (e.g., `Microsoft.ML.Tokenizers` 3.x preview, Lucene.Net.Analysis.* 4.8.0-beta). When upstream stabilizes, the comment documents the upgrade path.
- Native runtime dependencies (LibVLCSharp, OnnxRuntime GPU, Windows ML, etc.) are managed through NuGet packages with platform-specific binaries; redistribution/licensing notes are embedded in the props file comments.
- Project-to-project references coexist with NuGet packages; lockfiles capture both types of dependencies.

**Conventions and constraints**
- Versions must be pinned exactly in `Directory.Packages.props`; no floating ranges are used.
- Lockfiles are mandatory: `RestorePackagesWithLockFile=true` in `Directory.Build.props` enforces their use during restore.
- Only `nuget.org` is the default source; any deviation requires an explicit `packageSourceMapping` entry (currently only `Microsoft.ML.Tokenizers` → `dotnet-libraries`).
- SDK roll-forward is limited to `latestFeature` to avoid unexpected major-version jumps.
- Dependabot opens at most 10 concurrent PRs per ecosystem to keep update flow manageable.
