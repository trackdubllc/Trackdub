Trackdub is a .NET 10 monorepo built with MSBuild, using centralized package management and cross-platform solution files. The build system is defined by shared MSBuild props/targets at the repository root, which enforce consistent compiler settings, target frameworks, and publish behavior across all projects.

**Core build infrastructure:**
- `global.json` pins the .NET SDK to version `10.0.300` with `latestFeature` roll-forward policy, ensuring deterministic builds across the team.
- `Directory.Build.props` applies global MSBuild properties: `net10.0` as the default target framework, nullable reference types enabled, implicit usings on, warnings treated as errors, and lock-file restore enabled (`RestorePackagesWithLockFile=true`).
- `Directory.Build.targets` contains two critical MSBuild targets that run during publish:
  - `RemoveDuplicateCpuOnnxRuntimePublishAssets`: strips CPU-only ONNX Runtime DLLs when GPU providers (DirectML/WinML) are also present, preventing duplicate native assets in published output.
  - `RemoveDuplicateGenAiPublishAssets`: prefers CUDA GenAI native assets over base GenAI when both are pulled into the dependency graph.
- It also strips Windows-specific TFMs (`net10.0-windows*`) from non-Windows builds so the same multi-TFM solution can be built cross-platform without failing on Windows-only references.

**Package management:**
- `Directory.Packages.props` is the single source of truth for all NuGet package versions via `<ManagePackageVersionsCentrally>true</ManagePackageVersionsCentrally>`. This includes OnnxRuntime (`1.24.4`), Avalonia (`12.0.3`), xUnit, Spectre.Console, AWS SDK packages, OpenTelemetry, and many others.
- `NuGet.config` configures two package sources: `nuget.org` as primary and `dotnet-libraries` (Azure Artifacts) for pre-release `Microsoft.ML.Tokenizers` 3.x preview builds. A `packageSourceMapping` ensures only that specific package resolves from the secondary feed.
- Each project has a `packages.lock.json` file committed alongside it, enforcing reproducible restores.

**Solution structure:**
- Three `.slnx` solution files define the monorepo layout: `Trackdub.slnx`, `Trackdub.Inference.slnx`, and `Trackdub.Sdk.slnx`, each grouping related projects.
- Projects follow a layered architecture: Contracts → Domain → Application → Infrastructure → Inference → Composition, with separate CLI, Benchmarks, and DubBench applications.

**Development & CI tooling:**
- `mise.toml` pins development tools: `dotnet 10.0.302`, `node 22.16.0`, `pnpm 11.15.1`.
- `scripts/bs.ps1` is a PowerShell entry point for agent-driven workflows (codex, claude, devin, etc.) and control commands like `check`, `verify`, `publish`, and `run-avalonia`, delegating to `tools/agent-git-flow.ps1`.
- `scripts/ci/` contains CI helpers including `check-repository-boundary.py` and `run-avslnf-tests-sequential.sh`.
- GitHub automation lives under `.github/`: `dependabot.yml` for dependency updates, `CODEOWNERS` for PR review assignment, issue templates, and pull request templates.

**Cross-compilation & publishing:**
- The build system automatically strips Windows TFMs on non-Windows platforms, enabling cross-platform builds of the entire solution.
- Publish-time MSBuild targets resolve conflicts between multiple ONNX Runtime provider variants (CPU vs GPU vs DirectML vs WinML) by preferring the most capable native asset available.
- Native dependencies are managed through NuGet packages (e.g., `VideoLAN.LibVLC.Windows`, `VideoLAN.LibVLC.Mac`) with platform-specific runtime resolution handled at startup by dedicated locators.
