The module is a flat collection of standalone utility scripts organized by concern rather than a single application:
- `bs.ps1` is the Windows entry-point that dispatches to `tools/agent-git-flow.ps1` for agent workflows (codex, claude, devin, etc.) and control commands (`done`, `status`, `sync`, `check`, `verify`, `publish`, `run-avalonia`).
- `scripts/lib/` holds shared PowerShell functions (`RalphLoop.ps1`, `SpecQueue.ps1`) implementing an autonomous agent loop that reads `.specify/memory/constitution.md`, iterates over `specs/*.md` files looking for `<promise>DONE</promise>` signals, and invokes the chosen CLI agent.
- `scripts/ci/` contains CI-only tools: `check-repository-boundary.py` scans tracked files against regex patterns to enforce Apache-2.0 license boundaries and prevent desktop/cloud project names from leaking into public-core surfaces; `run-avslnf-tests-sequential.sh` runs each `*.Tests.csproj` in a `.slnf` sequentially with Inference.Tests last.
- Top-level Python scripts (`export-sepformer-onnx.py`, `inspect-deepfilternet-onnx.py`, `mirror_to_hf.py`) are independent one-shot tools using `onnxruntime`, `huggingface_hub`, `speechbrain`, and `pyannote.audio` to export, validate, and mirror ONNX models.
- Dependency direction is outward only: scripts depend on repo root paths computed via `Path(__file__).resolve().parents[2]` or `$MyInvocation.MyCommand.Path`; there is no internal package structure.
