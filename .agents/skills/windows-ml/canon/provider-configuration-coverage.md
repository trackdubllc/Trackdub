# Configuration coverage for all eight providers

Tier 1: Microsoft Learn only. Checked 2026-10-10. This is a coverage record, not a certification that any particular model runs. **Unresolved** means the cited Learn pages do not establish the detail; it does not mean the provider lacks the feature. Do not fill these cells using Trackdub decisions, another provider's settings, or external pages linked from Learn.

## Hardware and deployment

All catalog rows need compatible devices/drivers, Windows 11 24H2/build 26100+ and preparation/registration before selection. Catalog download depends on Windows Update, network availability and policy; installed packages still need the app dependency graph. Runtime self-contained/framework-dependent deployment is independent of EP sourcing. A bundled/hybrid EP alternative requires validating that particular runtime/EP combination. [Catalog prerequisites](https://learn.microsoft.com/windows/ai/new-windows-ml/supported-execution-providers), [installation](https://learn.microsoft.com/windows/ai/new-windows-ml/initialize-execution-providers), [sourcing](https://learn.microsoft.com/windows/ai/new-windows-ml/windows-ml-eps-vs-bring-your-own).

## Options and model/precision restrictions

For every row, the documented common configuration surface is `GetEpDevices()` → filter by EP and hardware type → `AppendExecutionProvider(environment, devices, options)`. Start with explicit selection before experimenting with device policies. Learn's `provider_specific_option` is illustrative, not a real key. An empty dictionary means no custom EP options; it does not prove that a provider/model needs none. [Selection API and placeholder](https://learn.microsoft.com/windows/ai/new-windows-ml/select-execution-providers).

| Provider | Options established in the reviewed Learn guidance | Model/precision restrictions and remaining gaps |
| --- | --- | --- |
| CPU | No CPU-specific EP option schema established. The Windows ML runtime documents session-wide thread-spinning keys; see below. [Run models](https://learn.microsoft.com/windows/ai/new-windows-ml/run-onnx-models) | ONNX compatibility depends on the shipped ORT. Complete CPU operator/opset/dtype/shape limits unresolved. [Models](https://learn.microsoft.com/windows/ai/new-windows-ml/models), [ORT mapping](https://learn.microsoft.com/windows/ai/new-windows-ml/onnx-versions) |
| DirectML | Explicit GPU device selection established; EP-specific option keys and required session flags unresolved in reviewed Learn guidance. [Selection](https://learn.microsoft.com/windows/ai/new-windows-ml/select-execution-providers) | No new operator coverage or quantization paths planned. Exact supported opsets, types, shapes and GenAI export requirements unresolved. DirectML operator API coverage is not an ONNX EP compatibility matrix. [Maintenance](https://learn.microsoft.com/windows/ai/new-windows-ml/webgpu-ep) |
| OpenVINO | Device class can be selected explicitly. Backend option keys/defaults unresolved; do not import them from Intel or ORT pages. [Selection](https://learn.microsoft.com/windows/ai/new-windows-ml/select-execution-providers), [delegation](https://learn.microsoft.com/windows/ai/new-windows-ml/supported-execution-providers#openvino-intel) | Per-device FP32/FP16/INT8 support, operator coverage, dynamic-shape limits and GenAI export constraints unresolved in reviewed Learn guidance. [Inventory](https://learn.microsoft.com/windows/ai/new-windows-ml/supported-execution-providers) |
| QNN | GPU/NPU selection established; backend paths, performance modes, context options and quantization configuration unresolved. [Selection](https://learn.microsoft.com/windows/ai/new-windows-ml/select-execution-providers) | Required precision/quantization, calibration, operator support, dynamic-shape limits and model-family compatibility unresolved. Do not claim every QNN device accepts the same export. [Requirements and external delegation](https://learn.microsoft.com/windows/ai/new-windows-ml/supported-execution-providers#qnn-qualcomm) |
| VitisAI | NPU selection established; EP-specific compiler/cache/backend option schema unresolved. [Selection](https://learn.microsoft.com/windows/ai/new-windows-ml/select-execution-providers) | Exact precision/quantization recipes, operator coverage, shapes and GenAI compatibility unresolved; documented driver range still applies. [Requirements](https://learn.microsoft.com/windows/ai/new-windows-ml/supported-execution-providers#vitisai-amd) |
| MIGraphX | GPU selection established; EP-specific option schema unresolved. [Selection](https://learn.microsoft.com/windows/ai/new-windows-ml/select-execution-providers) | Microsoft explicitly excludes GenAI scenarios today. Operator, shape and precision matrices remain unresolved. [MIGraphX restriction](https://learn.microsoft.com/windows/ai/new-windows-ml/supported-execution-providers#migraphx-amd) |
| TensorRT RTX | GPU selection established; engine-profile, precision, workspace and cache option keys unresolved in reviewed Learn guidance. Generic model compilation is documented separately. [Selection](https://learn.microsoft.com/windows/ai/new-windows-ml/select-execution-providers), [compilation](https://learn.microsoft.com/windows/ai/new-windows-ml/model-compilation) | Complete operator/precision/dynamic-shape profile limits and compatibility of a specific GenAI export unresolved. Do not infer restrictions from Trackdub failures or classic TensorRT. [Requirements and external delegation](https://learn.microsoft.com/windows/ai/new-windows-ml/supported-execution-providers#nvtensorrtrtx-nvidia) |
| WebGPU | Learn's working binding example uses an empty EP-options dictionary; provider-specific tuning keys are delegated to external ORT docs and remain unresolved here. [Example](https://learn.microsoft.com/windows/ai/new-windows-ml/webgpu-ep#enable-webgpu-ep) | FP32/FP16; INT4/INT8 quantization for LLMs. Non-LLM INT8 is unsupported on this path and can run at higher precision or fall back to CPU. Unsupported operators partition to CPU. Experimental; not recommended for performance-critical production workloads. Exact operator/shape matrix unresolved. [Limitations](https://learn.microsoft.com/windows/ai/new-windows-ml/webgpu-ep#limitations) |

The common **session** options `session.intra_op.allow_spinning` and `session.inter_op.allow_spinning` are disabled by default in Windows ML's ORT; setting them to `"1"` opts in. These are not interchangeable EP-specific keys. Measure performance and battery impact rather than copying them into every provider dictionary. [Thread spinning](https://learn.microsoft.com/windows/ai/new-windows-ml/run-onnx-models).

## Diagnostics by provider

The checks below are investigation steps derived from the cited lifecycle and logging APIs, not definitive error-to-cause mappings. A registered EP, successful session creation or a completed `Run` does not prove whole-graph acceleration. [Windows ML logs](https://learn.microsoft.com/windows/ai/new-windows-ml/logs).

| Provider | Check first | Evidence still needed |
| --- | --- | --- |
| CPU | Input/output metadata, shipped ORT version and original-model session creation. [Run models](https://learn.microsoft.com/windows/ai/new-windows-ml/run-onnx-models) | A real inference result with the model's correct preprocessing/postprocessing; CPU success does not verify an accelerator. |
| DirectML | Included runtime deployment, enumerated GPU device and session/selection logs. [Deployment](https://learn.microsoft.com/windows/ai/new-windows-ml/distributing-your-app), [logs](https://learn.microsoft.com/windows/ai/new-windows-ml/logs) | Runtime/module and session evidence before attributing absence to a DLL conflict; model/operator placement and driver behavior. |
| OpenVINO | Catalog offering, `ReadyState`, preparation `Status`, registration result and selected CPU/GPU/NPU class. [Install](https://learn.microsoft.com/windows/ai/new-windows-ml/initialize-execution-providers), [selection](https://learn.microsoft.com/windows/ai/new-windows-ml/select-execution-providers) | Exact Intel hardware/driver eligibility remains unresolved here; capture actual session errors and placement. |
| QNN | Catalog state, Hexagon driver for NPU, and GPU versus NPU device selection. [QNN requirements](https://learn.microsoft.com/windows/ai/new-windows-ml/supported-execution-providers#qnn-qualcomm), [selection](https://learn.microsoft.com/windows/ai/new-windows-ml/select-execution-providers) | Model/backend/precision compatibility; preparation success is not proof of successful QNN execution. |
| VitisAI | NPU presence and both ends of the documented driver range, then preparation/registration results. [Requirements](https://learn.microsoft.com/windows/ai/new-windows-ml/supported-execution-providers#vitisai-amd) | Actual compiler/session errors and model compatibility; a numerically newer driver is not automatically within range. |
| MIGraphX | RDNA/driver requirements, GPU selection and whether the workload is GenAI. [Requirements](https://learn.microsoft.com/windows/ai/new-windows-ml/supported-execution-providers#migraphx-amd) | Non-GenAI model execution and actual placement, not catalog visibility alone. |
| TensorRT RTX | RTX/driver requirements, registered GPU device, compile timing and cached compatibility result. [Requirements](https://learn.microsoft.com/windows/ai/new-windows-ml/supported-execution-providers#nvtensorrtrtx-nvidia), [compilation](https://learn.microsoft.com/windows/ai/new-windows-ml/model-compilation) | Validate the selected device against the compiled artifact; preserve external engine files and capture native/session errors. |
| WebGPU | Experimental package, explicit install/register results, selected device and GPU/CPU partition evidence. [WebGPU lifecycle and limitations](https://learn.microsoft.com/windows/ai/new-windows-ml/webgpu-ep) | Whether unsupported operators or quantized non-LLM input caused higher precision/CPU execution; unregister only after sessions are disposed. |

For catalog download failures, inspect `ExtendedError` and `DiagnosticText`, pending reboot, paused Windows Update and enterprise policy. For all providers, collect runtime/EP versions, drivers and session events through the documented rundown/ETW procedure; WPR capture needs administrator privileges and Windows Performance Toolkit. [Download troubleshooting](https://learn.microsoft.com/windows/ai/new-windows-ml/execution-provider-errors), [logging procedure](https://learn.microsoft.com/windows/ai/new-windows-ml/logs).

Compiled-model compatibility and source identity must both be validated. `EP_SUPPORTED_PREFER_RECOMPILATION` remains runnable; optimal-only reuse is a sample policy, not a provider restriction. [Cache validation](https://learn.microsoft.com/windows/ai/new-windows-ml/model-compilation). Each optional EP has separate license terms, and these do not determine model rights. [Notices](https://learn.microsoft.com/windows/ai/new-windows-ml/third-party-notices).
