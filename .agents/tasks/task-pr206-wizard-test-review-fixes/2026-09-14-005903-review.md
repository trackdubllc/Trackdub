# PR #206 wizard reset-flow test fixes (v1)

The change closes four PR-review findings on the full-pipeline wizard's reset test. It replaces reflection-based access to `PipelineTuiScreen._wizard` with a compile-checked `internal WizardState` accessor, rewrites `ConfigureFlow_ResetReplacesWizardStateWithDefaults` to drive all 12 wizard properties to non-default values and assert every one before and after reset, fixes the second Configure re-entry so the wizard actually re-activates (queueing a valid `es` language and asserting `HasOverlay`), and reconciles the FEAT-003 task record so its completion claim is backed by verification that was actually run. Production code is a single four-line accessor; the rest is test and task-record change.

Watch for: nothing blocking. The reset test's post-reset assertions overlap heavily with the standalone defaults test, but a mutation check (making `ResetWizardState` a no-op) was confirmed to fail the test, so it is not a tautology (confirmed). The `es`-on-re-entry behavior depends on the offline snapshot having a null target language; that holds here but is an implicit coupling (confirmed).

**Verdict**: APPROVED

## High-level view

Finding #3 (reflection) is resolved structurally, not cosmetically: the `GetField("_wizard")` string lookup and its `System.Reflection` import are gone, and the production type now exposes `internal PipelineWizardState WizardState => _wizard;`. Because `Trackdub.Cli` already declared `InternalsVisibleTo Trackdub.Sdk.Tests`, a future rename of the field now breaks the build rather than a test at runtime — exactly what the finding asked for.

Finding #1 (partial reset coverage) is resolved by walking the real wizard through every picker so all 12 properties leave their defaults, asserting all 12 at their non-default values, then asserting all 12 back to default after re-entry. The previously-unasserted fields — `RestorePan`, `MatchLoudness`, `AsrRefinement`, `BurnIn`, `ForceRerun`, `SubtitleSource`, `VideoEncoder`, `TimbrePolish` — are now all covered. The picker navigation in the test matches the production picker definitions exactly.

Finding #2 (dead re-entry) is resolved by queueing `PushTextWithEnter("es")` before the second Configure so the target-language guard passes and control reaches `BeginVoiceClonePickerAsync`, with `Assert.True(screen.HasOverlay)` proving a picker overlay is actually live after reset. The prior empty-string input returned early and never re-entered the wizard, so the reset it claimed to exercise never ran.

Finding #4 (premature completion) is resolved by choosing the "run the tests for real" remedy rather than downgrading status: the FEAT-003 `findings` now records build/test/format results actually observed in an environment where restore works, replacing the stale NETSDK1004/Tokenizers "could not run" note. Status stays `completed` because the acceptance criterion now genuinely passes.

### Exhaustive reset walk matches the production pickers

The rewritten test navigates each picker by `SelectedIndex` (starts at 0, `DownArrow` moves down, `Enter` selects), and every documented index lines up with the picker definitions in `PipelineTuiScreen`:

```
VoiceClone   [No, Yes, Back]                              Down,Enter        -> Yes
ExportFormat [auto, mp4, mkv, Back]                       Down,Down,Enter   -> mkv
SubFormat    [srt, vtt, ass, none, skip, Back]            Down,Enter        -> vtt => ["vtt"]
SubSource    [translated, transcript, bilingual, Back]    Down,Down,Enter   -> bilingual
Advanced     [Run, Timbre, Pan, Loud, ASR, BurnIn,        (re-opens at index 0 per toggle)
              ForceRerun, Video, Back]
  Timbre  index1  Down,Enter                 TimbrePolish  true -> false
  Pan     index2  Down×2,Enter               RestorePan    false -> true
  Loud    index3  Down×3,Enter               MatchLoudness false -> true
  ASR     index4  Down×4,Enter               AsrRefinement false -> true
  BurnIn  index5  Down×5,Enter               BurnIn        false -> true
  Force   index6  Down×6,Enter               ForceRerun    false -> true
  Video   index7  Down×7,Enter -> Video picker [auto, nvenc, ...]; Down,Enter -> nvenc
```

`HandleAdvancedChoiceAsync` flips a toggle and calls `BeginAdvancedPickerAsync` again, which builds a fresh picker at index 0 — this is what makes "navigate from the top each time" correct rather than an off-by-one trap. `SubtitleSource` maps `"translated" -> null` and any other value to itself, so selecting `bilingual` yields the non-default `"bilingual"`; the test asserts that, closing the specific gap the finding named (`RestorePan` and six others were toggled but never checked). `TargetLanguageOverride` reaches `"es"` from the language prompt at wizard start. The read-only `WizardState` accessor replacing the reflection helper adds no setter, so it exposes only what the assertions read.

### Re-entry now actually resets

`HandleRunAllMenuChoiceAsync` calls `ResetWizardState()` (which is `_wizard = new PipelineWizardState()`) and then, when the snapshot target language is null, prompts for a language and returns early with a status message if the input is empty. The prior test pushed `string.Empty`, so the second Configure returned before `BeginVoiceClonePickerAsync` and the wizard never re-activated — the "after reset" assertions were reading state from a flow that stopped at the guard. Queueing `PushTextWithEnter("es")` passes the guard, sets `TargetLanguageOverride = "es"`, and opens the voice-clone picker, so `Assert.True(screen.HasOverlay)` (which is `_picker is not null`) confirms the wizard genuinely re-entered. Because the walk stops at that first picker, the remaining fields (`SubtitleSource`, `SubtitleFormats`, `VideoEncoder`, etc.) stay at their post-reset defaults, and the test asserts exactly that. This is the difference between testing "reset happened" and testing "the early-return path happened to leave defaults" — the fix moves it to the former.
